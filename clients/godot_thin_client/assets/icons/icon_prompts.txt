# Bundled Icon Generation Prompts
#
# The icon twin of assets/terrain/texture_prompts.txt. These prompts generate the
# bundled PNG art behind the five icon families:
#
#   assets/icons/fauna/    herd map markers      (ui/FaunaSprites.gd)
#   assets/icons/sites/    food-site markers     (ui/SiteSprites.gd)
#   assets/icons/wonders/  Wondrous Site markers (ui/WonderSprites.gd)
#   assets/icons/stages/   settlement tokens     (ui/StageSprites.gd)
#   assets/icons/crops/    crop-ROLE row marks   (ui/CropRoleSprites.gd)
#
# The first four share ONE pipeline and ONE house style, so both are documented once
# here rather than per family. THE FIFTH DOES NOT — `crops/` is not a map marker, it
# is an inline mark inside a text ROW, and it overrides several of the clauses below.
# Read its own section before generating one; do not start from the house style.
#
# NOTE: prompts predating this file were never committed — only the shipped PNGs
# survive. The house style below is reconstructed from that art plus the wild-fowl
# prompt (kept verbatim as the reference exemplar). Add every new prompt here.
#
# ============================================================================
# PIPELINE
# ============================================================================
#
# 1. GENERATE at a large square size (1024x1024) on a plain solid MAGENTA
#    background. Any uniform background works — icon_key.py samples the four
#    corners — but magenta keys cleanest against earth-tone subjects.
#
#    ASK FOR NO TILE, AND CHECK THE COVERAGE NUMBER BEFORE ANYTHING ELSE. Current
#    image models read "flat vector game icon … on a magenta background" as a
#    request for an APP ICON and draw a dark rounded-square tile with the magenta
#    only as a surround. The key then does exactly what it is told — the corners
#    are magenta, so it keeps the TILE as the subject — and you get a dark chip
#    with a shrunken icon centred in it, which composites over the panel as a
#    visible box. Measured on the first `staple` pair: `icon_key.py` reported
#    **"subject covers 73.2% of the canvas"** where a bare wheat ear is ~15-20%.
#    That printed line is the cheapest detector there is, so read it every time —
#    a coverage figure far above the subject's honest share means something behind
#    the subject survived. The counter-clause is in every `crops/` prompt below
#    ("no rounded square, no tile, no card, no badge, no frame, no border … the
#    flat magenta touching the subject on every side") — carry it into any new
#    prompt rather than assuming "plain solid magenta background" is enough.
#
# 2. KEY OUT the background to transparency and normalize the framing:
#
#      python3 scripts/texture/icon_key.py in.jpg out.png --size 256
#
#    --size 256 matters: every shipped fauna sprite is 256x256 RGBA, and the
#    .import files set process/size_limit=64 against MapView's pinned
#    TEXTURE_FILTER_NEAREST. The script's own default is 512 — pass 256.
#    Other flags: --bg R,G,B (default: sampled from the corners), --lo (default
#    40) / --hi (default 90) bound the soft alpha ramp in 0-255 RGB distance.
#    Widen --hi if JPEG ringing leaves a halo; narrow it if thin features
#    (whiskers, antler tines) are being eaten. It trims and re-frames with a 6%
#    margin per side so the outline never touches the texture edge.
#
#    THE DEFAULTS ARE TOO TIGHT FOR AI-TOOL OUTPUT. Those defaults assume clean
#    input; generators hand back JPEGs, whose ringing around the subject leaves a
#    visible MAGENTA RIM on the keyed PNG. Measured on the seal render, residual
#    magenta fell 421 -> 325 -> 238 as --hi went 90 -> 130 -> 170. So for a JPEG:
#
#      python3 scripts/texture/icon_key.py in.jpg out.png --size 256 --lo 55 --hi 170
#
#    Always eyeball the keyed PNG for a pink rim before shipping it — a halo is
#    invisible at 1024 against magenta and obvious once composited over terrain.
#
#    THE .import SIDECAR GODOT GENERATES IS WRONG BY DEFAULT. It writes
#    mipmaps/generate=false and process/size_limit=0; every shipped icon needs
#    mipmaps/generate=true and process/size_limit=64. Correct the sidecar after the
#    first import and reimport, then diff it against a sibling (e.g. deer.png.import)
#    — it should match modulo the uid and the .ctex path hash.
#
#    JUDGE AT TRUE MARKER SIZE (24-41px), NEVER at 1024. The two seal candidates
#    inverted between the two: the one that looked bolder at full size lost its
#    head/snout separation when downscaled, and the sleeker one won. Downscale
#    candidates side by side against a shipped sprite before choosing.
#
#    A LOW, WIDE SUBJECT RENDERS SMALLER THAN ITS NEIGHBOURS, and that is correct.
#    The framing normalizes the silhouette's bounding box into the square, so a
#    hauled-out seal fills the width but only ~40% of the height and reads smaller
#    on the map than a tall quadruped. Preserving aspect is right; do not "fix" it
#    by cropping or stretching.
#
# 3. PLACE the PNG in the family's directory, named for its art KEY
#    (e.g. fauna/seal.png).
#
# 4. WIRE it. A fauna species needs BOTH tables or it silently draws an OS emoji:
#      - ui/FoodIcons.gd    HERD_SPECIES: "<keyword>": "<emoji>"   (the fallback)
#      - ui/FaunaSprites.gd SPRITE_PATHS: "<keyword>": SPRITE_DIR + "<file>.png"
#    The keyword is matched as a substring of the sim's `display_name`, longest
#    match first — so "Grey Seals" resolves via "seal". Aliases share art
#    (caribou -> reindeer.png, grouse -> fowl.png).
#
#    AN ALIAS IS ONLY HONEST WHEN NO ROSTER SPECIES IS BEHIND IT. `deer.png` once
#    served reindeer/caribou/elk/gazelle as well, and three of those four were real
#    entries in `fauna_config.json` — so Wild Elk, Wild Reindeer, Desert Gazelle and
#    Red Deer were four distinct species drawing one marker (issue #439). Before
#    aliasing a new keyword, check whether the sim actually ships a species under it;
#    if it does, it needs its own art. `caribou` survives as an alias precisely
#    because nothing in the roster is named that — it is a second English word for
#    the animal `reindeer` already covers.
#
# 5. VERIFY at TRUE marker size (10-41px), never in a fitted preview frame which
#    renders ~2.5x too big:
#      godot --path . res://tools/map_preview.tscn   ->  map_fauna_sprites.png
#
# ============================================================================
# HOUSE STYLE
# ============================================================================

# Every icon is a flat vector game marker, not an illustration. The skeleton:
#
#   Flat vector game icon of a <subject + its 2-3 identifying features>,
#   <calm neutral pose>, shown in side profile facing right, drawn as a bold
#   simplified silhouette with a thick dark charcoal outline around the entire
#   body, flat limited color palette in <two named tones> that stay clearly
#   lighter than the outline, simple two-tone shading, calm neutral facial
#   expression, crisp clean edges, centered with even padding on a plain solid
#   magenta background, the <subject> floating with no ground shadow and no
#   shadow beneath the feet, minimal graphic style that stays clearly readable
#   when scaled down to 24 pixels, strategy game map marker icon
#
# The load-bearing clauses — do not drop them:
#   * SIDE PROFILE FACING RIGHT — the whole set faces right; one that faces left
#     reads as broken in a roster row.
#   * THICK DARK OUTLINE — this is what keeps the silhouette legible at marker size
#     over any terrain, and it is the one clause every shipped icon has. Naming the
#     fills as lighter than the outline HELPS but is not strictly required: the
#     shipped deer and rabbit prompts omit it and read fine.
#   * NO GROUND SHADOW — a cast shadow keys out as a grey smear or survives as a
#     dirty fringe, and the marker is composited over terrain that supplies its own.
#   * READABLE AT 24 PIXELS — the real constraint. Fine texture, gradients and
#     background scenery all dissolve; ask for none of them.
#   * SOLID MAGENTA BACKGROUND — the chroma key depends on it being flat and uniform.
#   * CALM NEUTRAL POSE/EXPRESSION — these are map markers, not action art.
#

# ============================================================================
# FAUNA  ->  assets/icons/fauna/  (ui/FaunaSprites.gd)
# ============================================================================
#
# The KEY IS THE ART FILENAME STEM, not the sim's species name — a few species
# alias onto one file (see the notes). Coverage is complete: 18 files, 18 prompts
# (wolf.png landed with Predators Phase 1a — the first predator sprite; "Grey Wolf
# Pack" resolves via the `wolf` key, no longer the 🐺 emoji fallback. elk.png,
# reindeer.png and gazelle.png landed with issue #439, splitting the three roster
# species that had been drawing `deer.png`; steppe_runner.png and marsh_grazer.png
# landed with the same issue, and see the warning immediately below for why they
# were found late).
#
# ⚠ "COVERAGE IS COMPLETE" IS A CLAIM ABOUT THE SIM'S ROSTER, NOT ABOUT THIS FILE.
# It was written here — and in `FaunaSprites.gd`, and in `sprites-widgets.md` — while
# **Steppe Runners and Marsh Grazers were both drawing the 🦬 `HERD_DEFAULT` emoji**,
# and it had been false since those two species were added to `fauna_config.json`.
# The claim was checked the easy way, by confirming every key in `SPRITE_PATHS` had a
# PNG, which is a different question from every SPECIES having art and cannot detect a
# species the table has never heard of.
#
# The reason nothing caught it is structural and worth naming: **`SPRITE_PATHS` and
# `map_preview`'s `FAUNA_SPRITE_ROSTER` are both hand-written CLIENT-side lists, and
# the coverage frame enumerates the client's own table.** A species the table does not
# know is invisible to the frame by construction, so the frame cannot fail on it —
# exactly the blind spot that let the four cervids share one marker. The player-visible
# tell was that the OS emoji **faced LEFT** while every bundled sprite obeys the house
# style's "facing right" clause, which is a cheap thing to notice in a screenshot.
# `cargo xtask fauna-icon-guard` now cross-checks this against `fauna_config.json`, so
# the claim is verified rather than asserted. Re-run it after adding a species.
#
# THE FOUR CERVID-ISH SPECIES ARE THE SET MOST AT RISK OF READING AS ONE ANIMAL, so
# each prompt below names the ONE feature that separates it from the other three at
# 24px, and they are separated on SILHOUETTE first because hue cannot be trusted at
# that size over varied ground:
#   deer      — tall CROWNED antlers branching upward, head raised alert, mid-brown
#   elk       — antlers sweeping BACK past the shoulder, shaggy dark neck mane, pale rump
#   reindeer  — a forward BROW SHOVEL over the face, thick white neck ruff, stocky
#   gazelle   — HORNS not antlers (slim, ringed, lyre-curved), tiny body, dark flank bar
# A generated icon that could be swapped with another row of that list is a reject,
# whatever it scores on ground contrast.
#
# THE NO-TILE COUNTER-CLAUSE IS CARRIED BY `steppe_runner` AND `marsh_grazer` ALONE,
# and the other sixteen are the exception rather than the rule. The PIPELINE section
# says to carry it into any new prompt because "plain solid magenta background" alone
# reads to current models as a request for an APP ICON — measured at 73.2% coverage on
# the first `staple` pair. Every fauna prompt written before those two omits it,
# INCLUDING elk / reindeer / gazelle, whose renders happened to come back clean at
# 20-27% coverage; the clause is cheap insurance, not a fix for a bug those sixteen
# have. **Carry it into the next new prompt, and keep reading the coverage number
# either way** — that printed line is the actual detector, and no prompt clause
# replaces it.

# catfish.png — Silt Catfish (the delta/littoral resident shoal)
# MUST NOT LOOK LIKE sites/fish.png, which is a plump COOL BLUE-GREY river fish standing for the
# riverine_delta gathering site — the two can appear on the SAME hex (a delta tile with a shoal on
# it), so this is the fauna/seal.png vs sites/seal.png situation again: two files, deliberately
# different art, neither a stale copy of the other. Separated on THREE axes, all of which survive
# downscaling: WARM dark olive-brown vs the site fish's cool silver; a broad FLATTENED head with a
# wide downturned mouth vs a rounded snout; and the barbels, which the site fish does not have.
# THE BARBELS ARE THE HAZARD. Fine whiskers are exactly what `icon_key.py`'s alpha ramp eats (see
# the --lo/--hi note in the pipeline) and what dissolves at 24px, so the prompt asks for a FEW THICK
# ones — the same "chunky forms over fine detail" dodge the mammoth's fur and the boar's bristles use.
# If they still key out, narrow --hi rather than thinning them further.
#
# ---------------------------------------------------------------------------------------------
# V1 SHIPPED AND FAILED IN PLAY: "it blends in a lot with the background tile, almost invisible."
# The lesson generalizes past this icon, so it is recorded here rather than in a commit message.
#
# V1 asked for "warm dark olive-brown and muddy ochre" — which is, near enough, THE COLOUR OF THE
# GROUND IT SPAWNS ON. Measured (Rec.709 mean luma of the opaque fill vs the base textures of the
# terrains this species actually sits on): catfish fill **97**, against alluvial_plain 53,
# floodplain 59, rocky_reg **80**, navigable_river 89. A ~17-point gap against rocky ground is not
# a marker, it is camouflage. Ranked against the whole fauna set by mean |sprite − its terrains|,
# v1 came third from the BOTTOM (33.8, vs seal 77, sheep 99, cattle 112).
#
# TWO RULES FALL OUT OF THAT, and they apply to every future species:
#   1. THE HOUSE STYLE'S "lighter than the outline" IS NOT THE TEST THAT MATTERS. V1 passed it
#      comfortably (fill/outline separation 63, mid-pack — better than aurochs' 30). The test that
#      matters is contrast against the GROUND, and nothing in the style skeleton enforces it.
#      Before generating, look up what the species' `host_biomes` terrains actually look like.
#   2. HUE COLLISION COMPOUNDS IT. Brown-on-brown reads worse than the luma gap predicts, and this
#      subject has no protruding features to carry a silhouette the way antlers, ears or a comb do
#      — a fish is a smooth lozenge, so tone is doing ALL the work.
# The fix is NOT "add an outline" (it already has a thick one) — it is to move the BODY into a
# different tonal register from the earth: pale sandy flanks, cream belly, dark back for the
# two-tone read. Target fill luma ~140, i.e. the goat/seal band. The dark dorsal is what keeps it
# from collapsing into sites/fish.png's cool silver, so it must stay.
#
# V2 (the prompt below) SHIPPED and measures: fill luma **160**, mean |fill − host ground| **93.0**
# (worst case 48.4) — against v1's 97 / 34.8 / **8.3**, and comfortably past the seal's 90.8 / 46.2.
# Confirmed at 24/32/41px over all four real host grounds before shipping.
#
# KEYED AT `--lo 85 --hi 240`, NOT the pipeline's JPEG default of `--lo 55 --hi 170`:
#   python3 scripts/texture/icon_key.py in.jpg out.png --size 256 --lo 85 --hi 240
# THE PALE BODY IS EXACTLY WHY. This is the **white-species hazard** (see the sheep/fowl note in
# the fauna header) showing up in the KEYER rather than on the terrain: `icon_key.py` decides alpha
# by RGB DISTANCE FROM THE BACKGROUND, and a cream/buff subject sits far closer to magenta than a
# dark olive one, so the same ramp that was clean for v1 left a visible VIOLET FRINGE along the jaw
# and barbels of v2. Measured residual magenta fell 258 → 224 → 104 across the ramp; opaque pixels
# dropped only ~2% (11933 → 11678), i.e. the barbels survived — which is the trade to check, since
# widening the ramp is exactly what eats thin features. **Judge the fringe at 4x magnification over
# a MID-GREY field**, not on the magenta plate and not at 1:1: at 1:1 the violet edge is invisible,
# and against magenta it is invisible by definition.
# GENERAL RULE — **CORRECTED, and the original cost an icon nearly getting keyed to death** (issue
# #439, measured while keying the elk). This note used to read "the paler the subject, the wider the
# keying ramp it needs". That is the wrong variable. `icon_key.py` sets
# `alpha = smoothstep(lo, hi, dist)` where `dist` is EUCLIDEAN RGB DISTANCE FROM THE KEY COLOUR, so
# what decides the safe `--hi` is the subject's **hue proximity to the key**, not its LIGHTNESS.
# Distance from magenta is large for very dark AND very pale palettes and SMALLEST for warm
# mid-tones — tan, rufous, red-brown — which are the neighbours of magenta in RGB.
#
# Measured over the whole shipped fauna set (minimum distance-from-magenta across each sprite's
# fully-opaque pixels): fowl 103, wolf 112, cattle 122, deer 123, boar 124, aurochs 130, mammoth 132,
# seal 140, sheep 141, **catfish 151 — the FARTHEST of the set**. The catfish could afford `--hi 240`
# because its cool sandy-and-olive palette sits farther from magenta than anything else here, and
# being pale is merely correlated with that, not the cause. Note that the DEFAULT `--hi 170` is
# already above most of those minima, i.e. every shipped icon's warmest pixels are inside the ramp
# and slightly soft. That is the normal, accepted state.
#
# SO: `--hi` MUST STAY BELOW THE SUBJECT'S OWN MINIMUM DISTANCE, and raising it blindly destroys the
# icon rather than merely softening it. Measured on the elk candidate at fixed `--lo`: `--hi` 170 →
# 200 → 230 dropped fully-opaque pixels 22208 → 11469 → 6691, i.e. it dissolved HALF the animal —
# and raising `--lo` instead is no escape, since 55 → 70 moved ~5800 pixels out of opaque into the
# semi-transparent rim, eating the thick dark outline that is the house style's one load-bearing
# clause. The elk therefore shipped at the plain JPEG default.
#
# THE CHEAP CHECK, before touching either threshold: measure the subject's minimum
# distance-from-background over its opaque pixels, and compare the residual against THE SHIPPED SET
# rather than against an absolute — 3 (deer) to 209 (cattle) is the real band, median ~59, so a
# candidate scoring 52 needs no intervention at all. **A residual that merely LOOKS bad at 4x
# magnification is not evidence**; every icon in this directory has that faint violet rim.
#
# AND IF A SUBJECT IS GENUINELY TOO CLOSE TO THE KEY, MOVE THE KEY, NOT THE RAMP. `icon_key.py`
# samples the background from the four corners and `--bg` overrides it, so a warm rufous subject can
# be generated on a saturated CYAN or GREEN plate instead — worth ~240 distance against magenta's
# ~130 for the same tan, i.e. roughly double the margin, with no ramp change and no eaten outline.
# ---------------------------------------------------------------------------------------------

# gazelle.png — Desert Gazelle (issue #439; drew deer.png until then)
# SEPARATION FROM deer.png is the easiest of the three, and it is anatomical rather than stylistic:
# a gazelle wears HORNS, not antlers — slim, ringed, curving back in a shallow lyre — and it is
# TINY (body_mass 4 against the red deer's 60), so the proportions do the rest: short body, very
# long thin neck and legs. Nothing on this animal branches. If the render branches, reject it.
# GROUND-CONTRAST HAZARD — the catfish lesson, inverted: host_biomes is semi_arid_scrub, whose
# terrains measure luma 178 (hot_desert_erg), 197 (salt_flat) and 80 (rocky_reg). THE OBVIOUS
# COLOUR IS THE WRONG ONE — a sandy-buff gazelle is within ~20 of two of its three grounds and is
# camouflage by construction, which is exactly how catfish v1 shipped and failed. The gap between
# rocky_reg (80) and the pale pair (178/197) is where a fill has to sit, so aim for a MID rufous
# tan around luma 125–135 (the goat's band) and make the flank stripe carry the rest: real gazelles
# wear a hard dark chocolate bar along the flank above a white belly, which is a horizontal
# high-contrast edge — the one kind of detail that survives downscaling. It is doing the same job
# the catfish's dark dorsal does, and it must stay.
# KEYING — THIS IS THE MOST KEY-SENSITIVE ICON IN THE DIRECTORY, and the two hazards pull opposite
# ways, which is the whole difficulty of it. The ground-contrast rule above demands a warm mid
# rufous-tan; the corrected GENERAL RULE (catfish note) says warm mid-tones are exactly the palette
# CLOSEST to magenta in RGB — a representative rufous tan measures ~130 from it, at or below the
# lowest minimum in the shipped set (fowl, 103) and below the default `--hi` of 170. So key it at the
# plain default, do NOT widen the ramp under any circumstances, and measure the minimum
# distance-from-magenta over the opaque pixels before shipping.
# IF IT FRINGES ANYWAY, MOVE THE KEY RATHER THAN THE RAMP: regenerate on a saturated CYAN or GREEN
# plate (same prompt, swap the background clause) — the same tan measures ~240 from cyan, roughly
# double the margin — and let `icon_key.py` sample it from the corners as usual. That is the
# sanctioned escape hatch for a subject whose required colour collides with the key.
# WHAT ACTUALLY HAPPENED: the escape hatch was NOT needed. The shipped render measures min
# distance-from-key **140** with a residual of **18** — mid-pack for the set and better than deer
# (123) or cattle (122) — so it keyed at the plain default like everything else. The warning above is
# still worth its space, because it is a property of the REQUESTED PALETTE rather than of this one
