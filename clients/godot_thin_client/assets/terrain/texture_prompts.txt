# Terrain Texture Generation Prompts
#
# These prompts are for use with AI image generation tools:
#   - Midjourney (add --tile flag for seamless textures)
#   - DALL-E 3 (via ChatGPT Plus or OpenAI API)
#   - Stable Diffusion (enable "Tiling" option in settings)
#   - Adobe Firefly
#   - Leonardo.ai, Runway, or similar services
#
# After generating:
#   1. Ensure textures are seamless/tileable (use Photoshop/GIMP offset filter if needed)
#   2. Resize to 512x512 PNG
#   3. Save to assets/terrain/textures/base/ with naming format: XX_terrain_name.png
#   4. Restart Godot - textures load automatically
#

# ============================================================================
# RIVER EDGE TEXTURES (minor / major)
#
# These are NOT base terrain. Minor and major rivers run ALONG HEX EDGES, drawn by the terrain
# blend shader as a noise-perturbed band hugging the shared edge between two hexes. The shader
# samples these in continuous world space and masks them with the edge distance field, exactly
# how the canopy/peak overlays work.
#
# Requirements:
#   - RGBA PNG, 512x512, saved to assets/terrain/textures/rivers/
#   - Naming: XX_name.png -> 00_minor.png, 01_major.png
#   - FULLY OPAQUE water (alpha 255) — the shader's mask decides the river's shape, not the
#     texture's alpha. Do NOT paint banks, shorelines, or transparent edges into these; a
#     built-in bank would fight the shader's own noise-perturbed edge and read as a double rim.
#   - Seamless in BOTH axes, and non-directional for the same reason as 37 above.
#   - The two must read as different SIZES of water at the same zoom: minor = you can see the
#     bottom, major = you cannot. Keep the ripple/detail scale similar between them so they
#     look like the same world seen at the same distance.
# ============================================================================

# NOTE: the first pass at this prompt led with the pebble bed ("clear water over visible pebble
# and gravel bed") and every generation came back as GRAVEL with water as a faint overlay — a warm
# gold tile whose blue channel was its LOWEST (mean R-B of +53). At real river-band width the fine
# caustics mush out and colour dominates, so it read as a dirt road, and no colour grade could
# rescue it (grading a gold tile toward blue just makes grey mud). Lead with the WATER; demote the
# bed to "faintly visible through it".

#     rivers/01_major      ( 52,  73,  85)  bright  70   <- deep: dark, opaque

# The navigable river MUST NOT land near deep ocean. The first accepted candidate measured

# Navigable-river BANK (base/37) — the hex is a bank; the shader paints the channel on top
#
# NOTE the counter-intuitive grading rule here. The obvious move is to match the bank's tone to
# the biome it sits in (prairie, bright 112) — and one candidate did so almost exactly. That is
# WRONG: the worldgen tag solver promotes river-adjacent tiles to Floodplain (58) and
# AlluvialPlain (55), so a river corridor borders BOTH bright open land and dark fertile land.
# Matching either one perfectly just moves the flat<->flat dither's speckle to the other seam.
# The bank is graded to ~90 — the tone minimising the WORST-case gap across both families.
# (The floodplain placeholder used during development sat at 58 against prairie's 112, a 55-point
# gap, and the dither read as green confetti scattered over the grass. That is the failure mode.)
# Pick the FLATTEST, lowest-contrast candidate, not the most characterful one: contrast at the
# seam becomes noise, and a repeating feature (one candidate's moss blobs) becomes a visible
# lattice when tiled.
37_navigable_river: Seamless tileable river floodplain bank texture, top-down view, damp silty gravel and fine sand, scattered smooth pebbles, sparse patchy grass tufts, muted earthy browns and grey-greens, low contrast, soft even lighting, no water, no shoreline, no river, painterly style, 512x512 game asset

# ROAD SURFACE TEXTURES (the route ladder — issue #600)
#
# These are NOT base terrain, and they are the RIVER's kind of asset rather than the ocean's.
# A road runs THROUGH hex centres the way a minor river runs along hex edges: the shader draws a
# noise-perturbed band and these supply only the surface inside it. Nothing here is a shape.
#
# THE SHAPE PROBLEM WAS SOLVED BY READING THE RIVER CODE, and it is worth saying how, because the
# obvious route is expensive and wrong. A road is a per-tile improvement with 6 neighbours, so
# there are 2^6 = 64 connection patterns per rung; the first plan was a kit of drawn pieces —
# spokes, a hub, a terminus — at 3 plates per rung, 15 in all. It does not survive contact:
# butt-jointed spokes read as one road STRAIGHT THROUGH and as two planks at every bend, because
# each piece carries its own squared end and its own edge lines through the junction.
# `terrain_blend.gdshader`'s navigable-trunk pass already computes the exact piece that was being
# drawn — *"the arm SEGMENT: own centre -> the shared edge's midpoint"*, clamped so it stops at the
# boundary while the neighbour paints its own half — and it rounds every junction for free by
# keeping the direction of MAXIMUM COVERAGE (*"that max-coverage (== min-distance) pick is what
# rounds a 120 degree corner join for free — no spline math"*). So the whole kit collapses to ONE
# surface per rung, and a sixth rung later costs one image rather than 64.
#
# Requirements:
#   - RGB PNG, 512x512, saved to assets/terrain/textures/roads/
#   - Naming: XX_name.png -> 00_game_trail.png .. 04_rail.png (the rivers/ convention)
#   - FULLY OPAQUE, and never keyed. There is no background to remove and no alpha to author —
#     the shader's coverage decides the band's shape, exactly as it does for a river.
#   - NOTHING IN THE PLATE MAY BE OPEN. An early game-trail prompt asked for a track "broken by a
#     few short gaps" and the model painted the magenta plate THROUGH the band; keying made it
#     worse, not better (15% of the OPAQUE pixels carried a magenta cast at full alpha, so it was
#     not an edge artifact and no ramp touched it). Whatever the art leaves see-through becomes a
#     hole or a smear.
#   - THE ART MUST NEVER ENCODE FAINTNESS. `AnnotationRenderer._road_rung_opacity` already fades
#     each rung, and §4.13c fades a road in as it is worn. A prompt asking the plate to look faint
#     is asking it to do the renderer's job twice.
#   - Width, taper, meander and the fade are CONFIG, not art — the levers the river keeps in
#     terrain_config.json. Do not draw a narrow rung narrow.
#   - Seamless in both axes. Verify by tiling 3x3 and looking; a numeric wrap-vs-interior ratio
#     under about 2x is invisible on a noisy surface, and the eye is the judge.
#
# THE LADDER SEPARATES ON TWO AXES, and it has to, because width is now a config lever rather than
# a property of the art. Measured over the shipped five:
#
#     roads/00_game_trail  (129, 119, 107)  bright 120  sat 22   cool scuffed grey
#     roads/01_trail       (191, 168, 132)  bright 170  sat 59   pale warm sand
#     roads/02_dirt        (124,  93,  62)  bright  98  sat 62   dark warm brown
#     roads/03_paved       (106, 107, 109)  bright 107  sat  2   neutral grey stone
#     roads/04_rail        (106, 102,  94)  bright 102  sat 11   dark ballast + steel
#
# No two are close on both axes. The pair to watch when regenerating is game_trail vs paved —
# both desaturated, only 13 bright apart — and what keeps them apart is STRUCTURE: paved carries
# large stone cells with dark joints, the trail is a flat grain. Judge that pair together.
#
# GROUND CONTRAST IS A DIFFERENT QUESTION FROM THE LADDER, and the crowded band is the MIDDLE.
# A road sits on all 38 base textures, whose brightness runs 31..198, so counting how many land
# terrains fall within 15 of a candidate is the useful measure — not distance from any one of
# them. Measured: bright 110 collides with SEVEN (an exact tie with prairie_steppe and
# aquifer_ceiling), 98 and 121 with six each, and the pale trail at 170 with only THREE. Aiming a
# road at "mid grey-brown" is aiming at the most crowded value on the map.
#
# ⚠ RAIL IS THE ONE RUNG THE RIVER MECHANISM DOES NOT CARRY UNCHANGED. The river samples
# `v_map / (2.0 * hex_radius) * river_scale + best_tangent * (TIME * river_flow_speed)` —
# continuous MAP-SPACE UV, "exactly like the canopy", with the tangent used only as a scroll
# offset for flow and never to rotate the frame. Water has no orientation so that is free.
# Sleepers do: sampled that way they would stay locked to one screen direction whichever way the
# track ran. The fix is small and the shader already holds both parts — `best_tangent` and the
# signed distance to the centreline — so a rail pass samples a LOCAL frame,
# `vec2(dot(v_map, best_tangent) * scale, signed_dist / half_width)`.
# **Project the world position onto the tangent, NOT the per-hex segment parameter**: that
# parameter restarts at every hex boundary, so sleepers would step out of line tile to tile, while
# the projection stays continuous down a straight run and shifts only where the direction changes —
# which is where real track curves anyway. None of this blocks the four shipped rungs.
# ============================================================================
